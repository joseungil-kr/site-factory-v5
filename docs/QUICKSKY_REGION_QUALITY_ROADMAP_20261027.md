# 빠른스카이 — 지역별 자료 보강 및 선택적 색인 전략 (2026-10-27)

## 1. 현재 확인된 출처와 데이터 한계
- 현재 1,732개 지역명은 `data/regions/seoul_gyeonggi_current_dong.json`과 V4 `NAME_CANDIDATES` 기반. **행정동과 법정동이 혼재할 수 있으며**, 공식 현행 행정동으로 검증된 원장이 아니다.
- 행정안전부 공공데이터 [법정동 코드 OpenAPI](https://www.data.go.kr/data/15077871/openapi.do): 공식 표준 법정동 코드/지역명 확인에 사용 가능. API 사용에는 서비스키 필요. 이번 실행에서는 외부 API 키 발급이나 비공개 데이터 다운로드를 하지 않았음.
- 국가데이터처 공공데이터 [SGIS 행정구역 통계·경계](https://www.data.go.kr/data/15129688/fileData.do): 공개 통계/경계 자료가 있으나 자료 기준 시점(2024~2025), 법정동/행정동 코드와 V4 지역명 키 간 변환을 확인해야 한다.
- SGIS [행정구역 경계 OpenAPI](https://sgis.mods.go.kr/developer/html/openApi/api/data.html): 공식 행정경계/행정동명 API. 인증 Key 필요. `sgis.mods.go.kr` 공개 문서에 2021년까지 인자 예시가 있는 구간은 최신성 확인 후 사용.
- **주의:** 행정구역 이름·통계·경계 데이터는 지역 행정 정보이지 빠른스카이의 실시간 배차, 시공 실적, 작업가능 높이, 출장 요금을 증명하지 않는다.

## 3. 운영자 실자료 입력 원장 (필수 증거 게이트)
각 행정구역 키에 대해 최소 `regionLabel`, `officialCode`, `regionType`(행정동/법정동/불명), `officialSourceUrl`, `officialAsOf`를 채움. 운영 증거는 **별도**로 `canServe`(true/false/unknown), `serviceType`(당일/예약/상담후결정/불가), `operatorEvidence`(일자+제공자+증빙자료 링크), `supportedTonnes`, `conditions`, `lastVerifiedAt`을 둠.
시공 사례는 `jobEvidence`에 작업일/지역/실제 작업 유형/사용 장비/사진권리/검증자만 넣고, 개인정보·현장 정확 주소·고객 이름은 제거. 근거 없는 필드는 `unknown` 또는 null로 보관; 빈 값을 추정으로 채워 공개하지 않음.
권역 정보가 없는 지역명 페이지는 **색인 불허**. 일반 안전 안내만 있는 다른 지역과 동일한 템플릿을 이름 바꾸기만 해서 indexable로 전환하지 않음.

## 4. 단계별 품질 공개 계획
### A. 현재: noindex 전체 유지, 실제 사이트 화면 수정
기존 배포된 `sfv5-quicksky-preview` Worker에서 1,733개 페이지 접근은 유지하되 모든 문서를 noindex로 유지. 이미지·CTA·문장 오류 수정본을 **동일 Worker**에 업데이트하고 별도 HTTPS 검수로 확인.
### B. 홈페이지 **한 페이지만** 독립 검수·선택적 index
홈페이지는 서비스 안내·기기 상담·전화 연결 등의 방문자 가치가 지역별 문구 반복보다 높을 수 있음. 하지만 서울/경기 전체 상담 가능성, 고객의 실제 상담전화, 1톤/3.5톤/5톤 사업 제공 근거가 필요. 이를 확인한 뒤 운영자 정보(운영 주체, 상담 범위, 문의 시간, 장비 제원·요금은 필요 시 별도 문의)를 객관적으로 표시.
그 다음에 `publicIndexingScope=quicksky-home-only-*`와 **per-page robots** 지원을 별도로 구현·QA(현재 V5는 사이트 전체 indexable만 지원), 홈페이지 자기 canonical 1 URL·`sitemap.xml` 1 URL, 기타 1,732개 페이지는 noindex, preview workers.dev는 noindex 유지. 기존 1,733개 페이지 ID/번호는 삭제하지 않음.
robots에서 홈을 허용하는 동시에 나머지 URL은 **meta noindex를 크롤러가 읽도록 할 것**. `Disallow:/`로 모든 페이지를 가리면 봇이 noindex를 못 읽을 수 있어 혼용하지 않음. 이 릴리스는 전체 1,733페이지 승인과 별개.
### C. 검증된 지역만 순차 공개
시군구별로 실제 배차 가능·차별 정보가 있는 3~5곳의 파일럿부터 검수. 조건 미충족 지역은 계속 noindex. `indexablePaths` 목록/검증 날짜/원장 SHA를 고정해 sitemap·canonical·meta를 일치시킨 뒤 확장.
### D. IndexNow 및 검색엔진 등록
최종 **실제 indexable** URL 목록만 sitemap과 IndexNow 페이로드로 생성. 키 파일을 HTTPS 200으로 검증한 후 전송하고 200/202 응답 영수증 별도 보관. 기존 key=null 상태는 정상 키를 발명할 근거가 아님. 네이버/Google 소유확인·사이트맵 제출은 부모 담당과 중복하지 않음.

## 5. 정책 위험과 검증 기준
- Google [Spam policies](https://developers.google.com/search/docs/essentials/spam-policies)에서는 비슷한 지역별 검색어를 노려 동일 최종 목적지로 보내는 doorway 페이지 및 고유 가치 없는 대량 생성 콘텐츠를 경계한다.
- Google [People-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)에서는 원본성·경험·정확성·사용자 목적 달성을 강조한다. 수치 유사도 통과만으로 품질을 증명할 수 없다.
- 단지 규격화된 콘텐츠라는 이유로 자동 위반이라고 단정하지 않음. 각 URL의 방문자 효용과 실제 운영 근거를 검사한다.
