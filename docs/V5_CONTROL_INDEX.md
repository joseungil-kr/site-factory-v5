# 사이트팩토리 V5 통합 작업 창구
기준일: 2026-11-08 UTC. 공통 생성기 기준은 V5 main, 기능 버전은 V5.1이다. 저장소명이 V5라고 해서 기존 사이트별 브랜치나 V4 배포 의존성이 자동 이관되지는 않는다.

V4 문서는 역사·출처·잔존 배포 의존성의 증거로만 참조한다. 신규 제작 지침을 V4에서 병행 선택하지 않는다. 브랜치별 신규 규칙은 main 승인·검증 전까지 그 작업 범위의 후보이며, 상충할 경우 최신 사용자 지시를 확인한다.

## 현재 통합 범위
- V5 공통 지침 입구와 작업 원장을 연결한다.
- 기존 사이트를 재생성·재배포하지 않는다. 기존 Worker, DNS, 인증, 권한, 자산은 그대로 유지한다.
- 기존 사이트 수정은 신규 사이트 성과 확인 후 사용자가 별도 지시할 때 진행한다.
- 군 단위 근조화환 신규 시험은 기존 `site/v51-county-funeral-ownerprivate-20261107` 브랜치를 유지한다. 최신 사용자 지시는 작업자1 후속5로의 인계이며, 작업자5는 기존 산출물·검수 기록 창구다. 인수·실행 여부는 미확인이므로 [작업 원장의 원문 대조](V5_WORK_REGISTRY.md)를 확인하고 동일 브랜치 중복 제작·동시 수정을 시작하지 않는다.
- 개별 완성 HTML을 손으로 고치는 대신 문제 원인 → 프로토콜·POOL·생성기 수정 → 시험 문서 재생성 → 동일 문제와 새 표본 재검사를 반복한다.
- 최소 1% 표본(올림, 최소 1개), 각 90점 이상. 기술검사만으로 편집 품질 통과를 선언하지 않는다. 사실 오류·잘못된 주문 연결은 점수와 무관하게 실패다.
- 공개 처리·검색 등록, 비공개 접근제어 변경은 이번 문서 통합 커밋에 포함하지 않는다.
- 자동 검토 거절을 새 대화·다른 도구로 우회하지 않는다. 문서 통합은 작업자에게 명령을 전달했다는 뜻이 아니다.

## 배포 영향 점검
기준 main `8ca5de9ce0dcdb769bdc855afee26392999c654d`의 13개 workflow 원문 확인:
`publish.yml`, `staging.yml`, `daysky-1736-deploy.yml`은 workflow_dispatch이다.
이번 문서/검사기 변경은 배포 workflow를 수정하거나 호출하지 않는다.
main push는 `check.yml`의 offline tests/preview만 실행한다(운영 사이트 갱신 아님).
외부 webhook·Cloudflare dashboard의 별도 자동연결까지 확인한 것은 아니다.

## 완료 구분
지침 창구 통합 / 작업자 인계 수신 / 저장소 독립 빌드 / 운영 이관은 별도 단계다.
각 단계는 SHA·파일·테스트·실제 결과를 남긴다. V4를 지우거나 동작 중 배포 경로를 끊는 것으로 통합을 끝내지 않는다.
