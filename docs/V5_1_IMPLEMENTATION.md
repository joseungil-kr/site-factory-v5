# Site Factory V5.1: 신규 사이트 생성

V5.1은 별도 배포 서비스가 아닌 기존 생성기의 신규 사이트 제작 기능이다. 기존 사이트를 재생성하거나 배포하지 않는다. 신규 `scaffold-site`는 기획서 version 2를 만든다. 기존 version 1과 기획서 없는 사이트의 기존 렌더링은 유지한다. 생성기 변경을 main에 합치기 전 자동배포 workflow 및 기존 호스트 영향 범위를 확인한다.

## 제작 전에 준비할 자료
`site-spec.json`의 `research`에 `topic`, `price`, `order`별로 `source`와 `checkedOn`(YYYY-MM-DD)을 기록한다. 자료가 없으면 기획 검사는 실패한다. 작업자는 기존 자료를 먼저 찾고 필수 정보가 없으면 사용자에게 요청하거나 견적 상담 등 구체적인 대안을 질문한다. 자료 존재 검사만으로 내용의 진위·최신성이나 저작권을 보증하지 않는다.

`purposePools`는 목적별 항목을 담고 각 페이지의 `purpose`와 연결한다. 각 풀은 `introductions`, `sections`(`slot`이 `choice`와 `order`인 변주 항목), `faqs`, 그리고 상품형의 `productSkus` 또는 서비스형의 `serviceIds`를 포함한다. 페이지에 지정한 상품·서비스가 목적 풀 밖이면 빌드가 실패한다. 같은 페이지 ID/풀은 해시 기반으로 표현을 고정한다. 문장에 사용할 변수는 `{region}` 하나이며, 사실은 자료를 통해 확인해 넣는다. 미확인 가격·배송·실적·판매조건을 문장에 추정하지 않는다.

## 상품과 표시 정책
기존 `referencePrice`, `imageUrl`, `orderUrl` 필드는 유지한다. `referencePrice`가 있다는 이유만으로 현재 판매가를 표시하지 않는다. `priceConfirmed: true`, `priceEvidence`, `priceCheckedOn`이 함께 있는 상품만 금액을 화면에 표시한다. 자료의 실제 최신성은 사람이 확인한다. 금액이 확인되지 않으면 상품 링크로 연결한다.

사진은 `imageUseApproved: true`, `imageApprovalEvidence`, 해당 사이트 ID가 들어 있는 `imageApprovedFor` 목록, 유효한 `imageUrl`이 모두 있을 때만 표시한다. 원본·사용 범위의 근거는 운영 원장에 남기며, 기존 자산 보유나 판매처 이미지라는 이유만으로 권리를 추정하지 않는다. 현재 config는 상품 이미지 호스트를 승인된 주문 호스트로 제한한다.

## 문서와 구조화데이터
상품형은 제목과 소개 다음에 목적에 맞는 상품·가격·주문을 보여주고, 선택 안내·주문 안내·FAQ·명시적인 부모/자식 지역 링크가 이어진다. `parentPageId`는 확인된 관계만 지정하며 누락된 행정구역을 임의 추정하지 않는다. 존재하지 않는 부모와 순환 관계는 오류다. 부모가 없는 행도 삭제하지 않는다.

색인 가능한 상품 문서는 실제 화면에 대응하는 WebPage·ItemList·FAQPage를 만들고, 부모 관계가 있을 때 화면 breadcrumb와 동일한 BreadcrumbList를 만든다. 화면에 표시되는 확인된 가격만 동일한 Product/Offer로 표현하며, 확인되지 않은 가격·재고는 구조화데이터에 추가하지 않는다. 미리보기에는 운영 URL을 가리키는 JSON-LD를 넣지 않는다. 서비스형은 승인된 공개 단계에서 실제 페이지의 WebPage만 생성한다. 사이트별 자체 렌더러는 현재 이 공통 모듈을 자동 사용하지 않으므로 신규 어댑터를 명시적으로 연결해야 한다.

공통 검사에는 JSON-LD 파싱·기대 출력 일치, 목적별 선택 상품 카드 존재 및 실제 조합된 문구의 유사도 검사가 포함된다. 이는 사실·권리·방문자 관점의 사람 검수를 대체하지 않는다. 기존 지역 후보 전수 보존, 1% 표본 및 90점 기준, 승인·배포·보안 및 이미지 출처 절차는 그대로 따른다. 구조화데이터가 검색 순위나 리치결과를 보장하지 않는다.

## 공개 검수와 기존 사이트 보호

새 V5.1 기획의 공개 빌드 또는 공유 Worker 출시 준비 전 `python -m v5 review-sample --site <id>`로 검수 대상과 입력 digest를 출력한다. 목적별로 1%를 올림해 고정 추출하며 각 목적에 적어도 하나를 포함한다. 검수자가 결과를 `site-spec.json`의 `qualityReview`에 `approved`, `reviewer`, `reviewedOn`, `evidence`, `inputDigest`, `samples: [{id, score}]` 형태로 기록한다. 모든 지정 표본이 90점 이상이어야 공개 준비가 가능하다. 상품·페이지·문구 풀·기획 데이터가 달라지면 digest가 바뀌어 검수를 다시 해야 한다. 이 기계적 게이트는 작성된 점수가 사실인지나 텍스트의 자연스러움을 판단하지 않으므로 실제 검토와 증거가 필요하다.

기존 Daysky 자동 배포 workflow는 push 트리거를 제거하고 수동 실행만 남긴다. 생성기 코드를 main에 반영해도 기존 사이트는 배포되지 않는다. 기존 사이트 재생성이나 재배포는 사용자 별도 지시를 따른다.


## V5.1 군 근조화환 독립 검수 재작업 규칙 (2026-11-08, 시험 브랜치 한정)

- 이전 작업자의 자동·AI 평가 90~94점은 독립 합격 증거가 아니다. 계실장 독립 불합격 기준(홈 82, 담양 78, 영광 86, 연천 79)을 우선 실패 사례로 보존하고 재작업 후 완전히 새 HTML로 재검수한다.
- 원고를 늘리는 목적의 슬롯 추가를 금지한다. 첫 화면의 상품 카드/지역 링크에서 이미 제공한 금액·명칭·탐색을 본문·FAQ가 다시 반복하지 않게 **정보 책임 위치**를 나눈다. 필수 배송비 고지는 숨기지 않고 고객이 바로 확인할 위치에서 한 번 명확하게 제공한다.
- 군 페이지의 섹션은 검증된 상품 선택 기준, 수령지/빈소, 리본 표기, 공식 군의 읍·면 확인처럼 서로 다른 구매 과업을 담당한다. 군 목적에 도움이 되지 않는 배경 설명, 허위 상품 차이, 지역 배송 확약, 알 수 없는 꽃 규격은 쓰지 않는다.
- 광역 허브의 지역 고유성은 공식 원장상 소속 군 및 검증된 구매 맥락으로 확보한다. 단순 지역명 바꾸기와 구체적 근거 없는 지역 특성 창작 모두 금지한다. 복잡한 동의어 풀보다 방문자에게 실제 고유 정보를 제공한다.
- 자동 점수·Jaccard·정규식·페이지 수만으로 통과를 선언하지 않는다. 최소 1% 이상, **기존 독립 실패 페이지 4개를 반드시 포함**하여 현재 생성 HTML을 각각 읽고 90점 이상인지 근거와 감점을 기록한다. 실패 시 문구 풀/출력 구조/검수 규칙을 먼저 바꾸고 95개 전량을 다시 생성한다. 평가 점수는 사람 독립심사와 구분한다.
- 신규 시험 산출물만 수정한다. 이 재작업 단계에서 기존 사이트, main, 배포, DNS, 인증·권한·보안, 공개·검색등록은 변경하지 않는다. 검증된 비공개 URL이 없으면 배포로 보고하지 않는다.
