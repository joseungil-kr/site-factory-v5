## 3. 문구·본문 문제 — 코드 및 원문 대조

### 3.1 전국 생성 페이지

`v5/todayflower_regions.py`의 `_make_page()`가 만드는 전국 페이지마다 다음 문장을 넣는다.

- 도입부: `오늘 도착을 보장하지 않습니다.`
- 지역 안내: 법정동 코드와 2026-10-22 고정 자료를 방문자에게 설명한 뒤 배송·행정동 범위를 증명하지 않는다고 덧붙인다.

이는 주문에 필요한 선택 정보를 주기보다 판매자의 검증 한계와 내부 원장 정보를 방문자에게 설명하는 구조다. 법정동 코드·원장 시점·배송 미검증 여부는 내부 증거 문서에 보관하고 방문자 문장에서는 제거해야 한다.

동일 생성 파일의 문구 풀에는 `가정하지 마세요`, `단정하지 마세요`, `보장하지 않습니다`, `하지 마세요`, `확인해야 합니다`, `확인해 주세요`가 다수 들어 있다. 이러한 문구는 지역명과 조합되어 전국 생성 페이지에 반복 노출된다.

### 3.2 기존 33개 대표 페이지

`pages.json`의 33개 페이지를 필드 단위로 다시 세었다.

| 점검 패턴 | 발생 횟수 | 영향 페이지 |

| 보장·약속·단정하지 않음, 가정하지 않음 등 방어형 표현 | 25 | 17/33 |

확인 지시가 모두 잘못된 것은 아니지만, 같은 페이지에 주소·수령자·배송·가격 확인 지시가 연달아 반복된다. 고객이 무엇을 고르면 되는지보다 고객에게 확인 책임을 넘기는 느낌이 생기는 문단을 정리해야 한다.

## 4. 이미지·상품 증빙 상태

### 4.1 Todayflower 생성 WebP 5종

- 5종 모두 Git 원격에 저장되어 있고 실제 WebP 해상도 1448×1086, 각 Git blob SHA와 바이트 수가 원격 readback으로 확인된다.
- `site-spec.json`에는 ImageGen generation ID가 연결되어 있다.
- 그러나 생성 원본 PNG, 실제 실행 프롬프트 전문, 생성 UTC 시각, 원본 SHA256 및 원본 보관 위치는 현재 manifest에서 확인되지 않는다.
- 따라서 현재 상태는 고해상도 최종 WebP 보존은 PASS, 신규 공개용 전체 생성 provenance는 PARTIAL이다. 기존 운영 자산은 자동 삭제하지 않는다.

### 4.2 기존 promotion-plant 이미지

- Todayflower 마크업은 `hero-florist.webp`와 `moment-flowers.webp` 등 `assets/library/promotion-plant/` 계열 이미지를 사용한다.
- V5 `docs/image-governance/legacy-inventory-20261030.json`에서 promotion-plant WebP/SVG는 출처 증빙이 없는 `SOURCE_UNVERIFIED`로 분류되어 있다.
- 기존 공개 파일은 자동 폐기하지 않지만, 수정 공개본에서 그대로 새로 사용하려면 별도 출처 검증 또는 대체/제외가 필요하다.

### 4.3 fwith.co.kr 상품 사진·가격

- 상품 카드의 원본 링크와 SKU는 기존 구성을 보존한다. fwith 상품 사진의 Todayflower 사용에 관한 정확한 사용자 허가 원문은 이번 검토에서 회수하지 못했으므로, 다른 사이트의 승인 기록을 이 사이트로 확대 해석하지 않는다.
- 2026-11-06 확인 시 G067 60,000원, G073 66,000원, D144 53,000원, D149 65,000원, C206 120,000원, B205 109,000원은 fwith 상품 페이지에서 확인됐다.
- C200·B201은 fwith 직접 페이지가 이 검토 도구에서 열리지 않아 현재 가격을 독립 재확인하지 못했다. 저장된 10/30 가격을 11/06 현재 가격으로 단정하지 않는다.
- 따라서 기존 상품 목록/링크는 유지하되 가격 원장 전체 8개를 재확인하기 전 새 가격 표시·확장 배포는 보류한다.

## 5. 계획 메타데이터와 운영 상태의 차이

`site-spec.json`에는 `publishPolicy.mode=preview-noindex`, `production=false`, `domainConnected=false`, `publicReleaseApproved=false`, `images.approved=false`가 남아 있다. `site.json.publishEnabled=false`도 유지된다.

반면 `README.md`와 10/31 공개 배포 영수증은 V4 Worker가 `todayflower.nalmada.net` Host에만 index/canonical/sitemap을 부여하고 workers.dev는 noindex로 유지한다고 설명한다.

이 값들을 무조건 true로 바꾸면 preview fail-closed 안전장치를 훼손할 수 있다. 운영 Host 예외와 기본 preview 상태를 별도 필드/문서로 구분하는 방식으로 정합성을 개선해야 하며, 단순 플래그 변경은 하지 않는다.

## 6. V5 최신 전역 규칙과의 차이

2026-11-05 전역 `AGENTS.md` 및 `SITE_CREATION_PROTOCOL.md`는 방문자 중심 문체, 방어·훈계·AI 면책 캡션 제거, 실제 상품 사진·가격·직접 주문 링크, 이미지 출처 증빙, 390/1440px 실제 화면 검수, 사람의 의미·문체 검수를 요구한다.

이 전역 규칙은 이미 main에 존재한다. 이번 작업은 전역 규칙을 중복 수정하지 않고 Todayflower 전용 POOL·마크업·테스트·QA 문서를 해당 규칙에 맞게 갱신하는 방향이 적절하다. Todayflower 브랜치와 main은 크게 diverged 상태이므로 main 전체를 무리하게 병합하지 않고 필요한 검사만 사이트 범위에 한정해 반영한다.
